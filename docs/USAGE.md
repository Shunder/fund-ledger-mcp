# 录入和查询

## 期初与交易

本版适用于以人民币计价、披露单位净值的场外公募基金。份额、净值和金额均传十进制字符串，金额单位为元。持仓用 (platform, code) 区分，自定义平台名称应保持一致；不同份额类别通常有不同代码。day、orderDay 使用 YYYY-MM-DD。期初快照视为该日收盘状态。查询当前市值采用最近已披露单位净值，并随结果显示日期。

| 操作 | 输入和口径 |
| --- | --- |
| 新增、导入、更正期初 | platform、code、day 必填，可填 name、category、shareClass。通常传 shares 与 cost 或 unitCost。可用 marketValue / snapshotNav 推份额，或 marketValue / (1 + returnPct/100) 推成本，再由 unitCost 推份额。仅有市值和成本单价时会尝试查精确日期的披露净值。不可用则请求补齐。returnPct 的 -25 表示 -25%。 |
| 待确认申购 | kind=buy、status=pending、orderDay、id、platform、amount。代码尚不确定可给 name；确认后用相同 id、原 orderDay、平台和 kind，补录实际 code、day、shares、nav、fee 和 amount，状态改 confirmed。 |
| 申购 | kind=buy，amount 为实际支出含费，shares × nav 约等于 amount − fee。 |
| 赎回 / 清仓 | kind=sell，amount 为扣费后实收，shares × nav 约等于 amount + fee。清仓传实际全部确认份额，仍保留流水。 |
| 现金分红 | kind=cash_dividend，amount 为分红金额，exDay 为除息日，day 为到账日。 |
| 红利再投资 | kind=reinvest，amount 为分红本金，并提供再投的确认份额及净值，exDay 为除息日，day 为新增份额确认日。 |
| 基金转换 | kind=convert，原 code、shares、nav 与 targetCode、targetShares、targetNav 同时提交。amount 是转出毛额，fee 是该转换总费用。支持同日、同平台、同币种且全额转入。 |
| 更正/删除 | update_holding 更正期初行。普通流水更正可先删除错误流水再登记；两次操作分别确认。删除错误流水会回放余下历史。清空持仓历史需 delete_holding、预览及确认。有跨基金转换的持仓须先处理关联记录。 |

交易 id 可用凭证参考号或保存的随机 ID；请勿使用完整银行账户号。相同 id、相同内容重试不会生成第二笔交易。新建一笔真实定投时要用新 id。除息早于结算时，先按除息日确认权益；普通同日流水按登记先后回放。confirm_changes 仅在用户核对预览后调用。期初属于已有持仓，后续买入和卖出应登记流水。

CSV 表头等同于 holding 字段名。最简的虚构样例为以下两行，单次最多 200 行。AI 解析自然语言后也可直接生成相同字段的 JSON rows。

```csv
platform,code,day,shares,cost,name,category,shareClass
演示平台,000123,2025-04-01,100.25,110.00,虚构样本,混合,A
```

## 同一只基金在两家平台分红，怎么对账？

假设两个平台各有 100 份，除息前净值 1 元。3 月 4 日每份分红 0.10 元，净值降至 0.90 元，3 月 5 日结算。用两笔流水分别登记平台选择的分红方式。

| 对账时点 | 演示钱包 · 红利再投资 | 演示银行 · 现金分红 |
| --- | --- | --- |
| 除息日 | 100 份，市值 90 元，应收 10 元 | 100 份，市值 90 元，应收 10 元 |
| 结算日 | 凭证确认再投 11.11 份，合计 111.11 份，成本增加 10 元 | 仍持 100 份，到账 10 元，基金成本不变 |
| 外部资金流 | 0 元 | 到账日流出组合 10 元 |

用 `get_holding` 指定基金代码，可逐平台核对 `dividendReceivable`（应收）、`cashDividendsReceived`（累计现金到账）、`dividendsReinvested`（累计转入成本）和 `reinvestedShares`（累计新增份额）。`marketValue` 是份额市值，`assetValue` 包含应收红利。也可用 `get_transactions` 按平台、代码、状态和类型筛选定投或转换流水，转换的转出与转入代码均可查询。

凭确认单填写红利金额、份额及计算净值。下面是虚构的再投资交易，可交给 `preview_portfolio_changes` 的 `record` 操作。省略 `exDay` 会沿用已有账本的同日除息和结算口径。只知道预计分红时先记录 pending，待实际份额确认后用同一 id 补齐，再回放除息日。到账日晚于用于计算份额的净值日时，账本在确认日入账份额，此前以应收金额计价。

```json
{"id":"demo-div-01","platform":"演示钱包","code":"990001","kind":"reinvest","orderDay":"2025-03-04","exDay":"2025-03-04","day":"2025-03-05","amount":"10.00","nav":"0.9000","shares":"11.11"}
```

## 收益口径

- 在有前一可用净值且区间数据覆盖完整时，无交易日收益等于期初份额乘两次披露单位净值之差。日末确认的交易按“期末资产 − 期初资产 − 外部净流入”计算。资产包括尚待结算的应收红利。申购是正流入；赎回实收和现金分红是负流入；红利再投资外部流量为零。转换的内部转出/转入在组合层抵销。管理费和托管费已经包含在净值中。
- 已实现收益来自按移动平均法结转的赎回损益及获得的分红，未实现收益为最新市值减剩余成本。再投资的红利同时记为已实现分红和新份额成本。份额与金额全程 Decimal，汇总后再按分四舍五入。
- 每日组合输出包含 day、各基金 navDay、previousNavDay、dataUpdatedAt、分平台及按代码合计。更新时间是本地获取或订正该净值的时间，供应方披露日另列。全部活跃仓位当日可计算才返回日总盈亏，knownDailySubtotal 为已披露部分。周末、节假日、QDII 延迟或净值缺失时，查看上次披露日或手动回补。
- 区间统计默认按日末现金流，以每日资产增长因子连乘得到 TWR，最大回撤来自相同资金流调整后的指数。区间首日前的收盘为基准，首笔记录为申购时从首笔净投入计算，空账户首日用当日投入作收益率分母；以期初快照开始的账本从首个可观测收盘起算并标注。内点可按当时已知的最近净值估价，截止日需要完整估值；跨市场披露日不同可导致指标暂缺。历史曲线提供报价/交易日期及查询截止日，无数据的时期不会补造曲线。
- XIRR 使用实际日期、365 天年基、区间起止资产价值及外部资金流，在保守的唯一根条件下用 Decimal 二分求解。不满足条件、区间不足或无法验证区间现金流时返回 null。不同历史长度与现金进出会使 XIRR 和 TWR 不同。
- 期初以前的赎回、分红及现金流未知。持仓已有浮盈可由导入成本计算；历史曲线、XIRR 和 TWR 的覆盖期从可靠记录开始。estimated、basis 和 basisDay 随推导仓位返回。

## 自然语言示例

1. “我有一张基金快照，只有市值、成本单价和收益率。请先问我快照日期与平台，列出推导份额、依据和基准日，等我核对后保存。” 缺少同日估值依据时可提供确认份额。
2. “在演示平台定投了 1000 元某指数基金，尚未确认。请先按待确认记录，把流水 ID 告诉我。” 确认后再说“用该流水 ID 补上确认日、代码、份额、净值和费率对应的实际费用”。
3. “按上海日期查今天赚了多少。按基金合并不同平台，把 QDII 的净值日期和待披露部分单列。”
4. “我有多少只不同的基金？列出总成本、市值、已实现、未实现和累计收益。”
5. “统计最近 30 天收益和最大回撤，列出资产曲线与实际覆盖起点。如果今天还没披露，再给我截至最近完整披露日的结果。”
6. “用我的真实持仓、上一完整披露日盈亏和可取得的相关市场指数生成早报。注明各数据日期，把盘中估值单列。” 海外报价只覆盖上游支持的证券 ID，全面的全球新闻和市场行情需要另行授权的数据源。
7. “在新会话中选择同一个 MCP，查询上次保存的持仓和最近三笔流水。” 同一 issuer 和 sub 会取回相同的 PostgreSQL 账本。

## MVP 边界

支持正份额、非负成本、人民币单币种及普通单位净值。货币基金的万份收益、外币份额、负成本法、侧袋、份额拆并、跨日转换、跨账户资产划拨和现金子账户均需额外模型。不要将这些业务按普通申赎录入。来源标记的无法解释的公司行动会让受影响指标显示 reconcile_corporate_action；补录正确除息日交易后回放。来源未标注的公司行动仍需投资者核对确认单。预估或预测收益不进入账本。若权益登记后、除息日前已卖光，当前回放无法自动确认该笔权益。平台可能采用不同的成本法与到账日，应以原始交易单核对差异。服务不储存或使用银行登录资料。
